# 资料来源的字段优先级

2026-09-21 确认的当前口径。本文替代 `procurement-source-2` 中“关联支付审批后只允许该来源、其他资料永不回退”的来源排除规则；旧计划、测试记录和已确认快照保留用于追溯。代码验证、部署和线上验收须分别记录，本文不代表已经上线。

## 默认值和人工选择

有效资料按“支付申请 → 国际物流审批 → 商品采购支出 → 其他合法证据”排序，逐字段选择默认值。高优先级来源缺少某个字段时，继续查看下一来源；低优先级提供的合法值始终保留为候选，允许人工改选。显式人工选择在重新排序、预览和后续核对中保留，来源失效或证据变化须明确提示并重新核对。

来源优先级不等于字段语义。支付金额、运费、物流计费单价不能作为商品采购价。国际物流货物表（审批正文及对应附件、评论行）的专用“货值”列表示该采购行总额；这一明确语义在币种缺失时默认人民币，并不限于专用装箱附件。其他来源的未知币种继续待核对。采购数量、采购行总额、商品单价与本次发货数量分别保存；数量、币种和物料身份足够明确时，先从采购行总额及采购数量核对商品单价，再按实际发货数量估值。

## 来源目录和校验

已绑定或已采用支付资料的批次仍保留本批当前有效的国际物流正文、评论、专用附件、明确关联采购资料及当前版本手工附件。按票支付资料继续使用已经验证的本票范围，不能读入同一月结单的其他票。每条资料保留自己的审批企业、实例、附件和版本依赖，不能把支付审批的上下文套到国际物流或手工来源。

普通列表和资料目录只读本地归档、附件元数据及缓存，不拉取上游、不调用 AI、不写业务数据，也不为列举工作表打开工作簿。缺归档、文件损坏、审批失效等状态仅影响对应资料；其他合法证据仍可分析和选择。跨批次、跨企业、身份不符、已拒绝或撤销、停用或撤回资料、过期哈希仍被拒绝，优先级不能绕过这些检查。

## AI 填充的货值与字段核对

同一物料编码下，来源和现有行只有一侧缺规格时，必须有唯一行匹配和可定位的来源凭据；两个明确规格冲突时不采用。新采用记录保存来源行与目标行身份。实发数量、单位先确定，再按同一证据的采购总额和计价数量折算本次发货货值。真实单位冲突需要人工核对，同金额但计价依据不同的候选不能合并。

确认前按服务端预览核对将填入的字段。可写的推荐值默认填入，可从确有备选的字段切换来源。单独待核对的字段保留现值，其余可写字段可照常确认。若预览还会新建付款申请关联，须先处理待核对字段或调整资料来源。保存后可以在物料表中手工调整发货货值等可编辑字段。明确的零价有独立证据；空值、未知币种、未换算的数量和没有包装依据的尺寸继续待补。原始采购币种和单价不会被显示用的推算值覆盖。

## 历史与写入边界

已存在的活动批次在下一次资料分析或核对时采用新规则，不以创建日期区分。旧规则下生成的草稿需重新分析；不自动批量重写历史业务值。已确认的历史版本、来源快照和审计记录保持原状，新核对产生的新采用仍通过现有人工确认流程。

分析、预览、明确采用、试算、确认成本和 ERP 推送分别遵循原有操作边界。来源排序和目录查询本身不会确认费用、改写人工值、确认成本或推送 ERP。费用的按票采用规则见[按票运费与装箱变更运行手册](shipment-freight-adoption-operations.md)。
